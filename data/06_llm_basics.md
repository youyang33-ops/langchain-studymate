# 大模型基础（面试八股）

## Transformer 与注意力机制

现在的主流大模型（GPT、Qwen、DeepSeek、Llama）都是 Decoder-only 的 Transformer：根据前面所有 token 预测下一个 token，一个一个生成。

自注意力（Self-Attention）的计算：每个 token 生成 Query、Key、Value 三个向量，用 Q 和所有 K 做点积得到"该关注谁"的权重，再对 V 加权求和。公式是 Attention(Q,K,V) = softmax(QKᵀ / √d) · V。除以 √d 是为了防止维度大时点积过大，导致 softmax 梯度消失。多头注意力（Multi-Head）是并行做多组注意力，让模型同时关注不同类型的关系。

注意力的计算量随序列长度平方增长，这是长上下文昂贵的根本原因。

## Token 与上下文窗口

模型处理的单位是 token 而不是字。英文一个 token 约 0.75 个单词；中文一个汉字通常是 1 到 2 个 token，具体取决于分词器。API 按输入和输出 token 计费，输出通常更贵。

上下文窗口指单次请求能容纳的最大 token 数（输入加输出）。窗口大不等于效果好：研究发现模型对长上下文中间部分的信息利用较差，被称为 Lost in the Middle。所以关键信息应放在开头或结尾，RAG 也要控制注入的片段数量。

## KV Cache

生成每个新 token 时，前面 token 的 Key 和 Value 不会变，把它们缓存起来就不用重复计算，这就是 KV Cache。它用显存换速度，也是长上下文推理显存占用大的原因。各厂商的"上下文缓存 / Prompt Caching"计费优惠，本质上是复用了相同前缀的 KV Cache，所以应把固定不变的系统提示词放在消息最前面。

## 采样参数

- **temperature（温度）**：对 logits 除以温度后再做 softmax。温度越低，分布越尖锐，输出越确定；越高越随机、越有创意。信息抽取、分类、工具调用用 0 到 0.3；创意写作用 0.7 到 1.0。
- **top_p（核采样）**：只从累计概率达到 p 的最小候选集合中采样，截掉长尾低概率词。通常调 temperature 和 top_p 其中一个即可。
- **top_k**：只从概率最高的 k 个 token 中采样。
- **max_tokens**：限制输出长度，防止失控和超支。

## 幻觉的成因与缓解

成因：模型本质上是在预测"看起来合理"的下一个词，而不是检索事实；训练数据有错误或过时；问题超出了知识范围但模型倾向于给出回答；解码时的随机性。

缓解：RAG 提供可靠资料并要求引用；提示词明确"不知道就说不知道"；降低 temperature；把计算、查询类任务交给工具；对输出做校验或让另一个模型核查；高风险场景人工审核。

## RAG 还是微调

| | RAG | 微调（Fine-tuning） |
|---|---|---|
| 解决什么 | 让模型知道新知识、私有知识 | 让模型学会特定格式、风格、领域任务 |
| 知识更新 | 改文档即可，实时生效 | 需要重新训练 |
| 可解释性 | 可以给出引用来源 | 难以追溯 |
| 成本 | 低，主要是检索和 token 成本 | 需要标注数据和 GPU |
| 典型场景 | 企业知识库问答、客服 | 固定格式输出、特定领域术语、小模型专精 |

实践中的常见结论：要补充知识优先用 RAG；要改变行为和格式才考虑微调；两者可以结合。

## LoRA 是什么

LoRA（Low-Rank Adaptation）是最常用的参数高效微调方法。它冻结原模型权重 W，只训练一个低秩增量 ΔW = B·A，其中 A、B 是两个很"瘦"的矩阵，秩 r 通常取 8 到 64。可训练参数量只有原来的千分之一到百分之一，显存需求大幅下降，并且训练出的 LoRA 权重很小，可以针对不同任务切换。QLoRA 在此基础上把原模型量化到 4 bit，进一步节省显存。

## 推理模型

DeepSeek-R1、Qwen 的思考模式这类推理模型，会在回答前先生成一段较长的思考过程（Chain of Thought），复杂推理、数学、编程任务效果更好，但延迟和 token 成本更高。简单任务不需要开启思考模式。

## Prompt Engineering 常用技巧

- 角色设定和明确的任务描述
- Few-shot：给出几个输入输出示例
- Chain of Thought：要求"一步步思考"，提升推理类任务准确率
- 结构化输出：要求 JSON 格式，或使用结构化输出功能
- 分隔符：用三引号、XML 标签把指令和资料分开，降低提示词注入风险
- 把复杂任务拆成多个简单步骤，用工作流串起来
