# Agent 岗位面试准备

## 高频问题与回答要点

### Agent 陷入死循环或反复调用同一个工具怎么办

设置最大模型调用次数和工具调用次数（如 ModelCallLimitMiddleware）；工具返回清晰的错误信息，让模型知道为什么失败；在系统提示词里明确停止条件；记录调用轨迹，用 LangSmith 定位是哪一步出问题。

### 如何减少 Agent 的幻觉

用 RAG 提供可靠资料并要求标注来源；提示词要求"资料没有就说不知道"；计算、日期等确定性任务交给工具，不让模型心算；对关键输出做结构化校验；高风险操作加人工审批。

### 工具太多时模型选不准怎么办

精简和合并工具，写清楚每个工具的使用场景；按任务阶段动态提供工具子集（如 LLMToolSelectorMiddleware 先用小模型挑选相关工具）；拆分成多个专业子 agent。

### 上下文窗口不够用怎么办

对话摘要（SummarizationMiddleware）；清理过期的工具调用结果；RAG 只取最相关片段；把长期信息存入外部存储（LangGraph Store），需要时再检索。

### 怎么评估一个 Agent 的效果

构造测试集，覆盖常见路径和边界情况；指标包括任务完成率、工具调用准确率、步骤数、延迟、token 成本；用 LLM-as-a-judge 打分并人工抽检；线上收集用户反馈。

### 不用框架，你怎么实现一个 Agent

维护消息列表，循环调用模型；如果返回 tool_calls 就执行对应函数，把结果作为 tool 消息追加；没有 tool_calls 就返回答案；加上最大轮数限制和异常处理。能讲清楚这一点，说明你理解框架背后的本质。

### MCP 是什么

Model Context Protocol，由 Anthropic 提出的开放协议，统一了"模型应用如何连接外部工具和数据源"。工具提供方实现一次 MCP Server，就能被各种支持 MCP 的客户端使用。LangChain 可以通过 langchain-mcp-adapters 把 MCP 工具转成 LangChain 工具。

### RAG 检索不准怎么排查和优化

先定位问题出在哪一环：用测试集分别评估检索（正确片段有没有被召回）和生成（召回了但回答错）。检索问题依次检查：切分是否把关键信息切断；Embedding 模型是否适合中文和领域；是否需要 BM25 混合检索来处理专有名词；是否需要 Rerank 精排；用户问题是否需要改写。每次只改一个变量，并用命中率、MRR 对比效果。

### 为什么要混合检索，怎么融合

向量检索擅长语义和同义表达，但对型号、错误码、人名等精确匹配不如 BM25。两路结果用 RRF 按排名融合，不需要统一分数量纲。

### Rerank 为什么比 Embedding 准，为什么不全部用 Rerank

Embedding 是双塔结构，问题和文档分别编码，文档向量能预先计算，所以快；Rerank 是交叉编码，问题和文档一起输入，精度高，但每一对都要实时计算，无法对海量文档使用。所以先用向量和 BM25 召回几十条，再用 Rerank 精排取前几条。

### 多 Agent 和单 Agent 怎么选

能用单 Agent 解决的就不要拆。工具过多、子任务需要不同的专业提示词、上下文被中间结果撑满、子任务可以并行时才考虑多 Agent。流程固定时优先用 LangGraph 工作流，比让模型决策更可控、更便宜。

### Supervisor 模式的上下文隔离是什么意思

子 Agent 内部的多轮工具调用和中间结果只保留在子 Agent 自己的上下文中，主管只收到最终汇报。这样主管的上下文不会膨胀，也不会被无关细节干扰。

### Function Calling 和 MCP 有什么区别

Function Calling 是模型能力，决定"调用什么、传什么参数"；MCP 是应用层协议，规定工具如何被发现、描述和调用。MCP 提供的工具最终仍然通过 Function Calling 被模型使用。

### 流式输出怎么实现

后端用 agent.astream 并设置 stream_mode="messages" 获取逐 token 输出，通过 SSE 推送给前端；同时订阅 updates 模式，把工具调用、人工审批等事件也作为不同类型的 SSE 事件推送。要注意过滤掉摘要等内部模型调用产生的 token。

### 用户量上来后 Agent 服务要注意什么

接口全部异步化；checkpointer 换成 PostgreSQL 以支持多实例；模型接口加超时、重试和降级；按用户限流；监控 token 成本；用 LangSmith 或 Langfuse 做链路追踪。

### 什么是提示词注入，怎么防

攻击者在用户输入或被检索的文档中写入"忽略之前的所有指令"等内容，诱导模型执行非预期操作。防御：用分隔符区分指令和数据；有副作用的工具加人工审批；工具权限最小化；对工具参数做严格校验；不在提示词中放密钥。

### Dify、Coze 和 LangChain 怎么选

Dify、Coze 是低代码平台，拖拽搭建工作流、自带知识库和发布渠道，适合快速验证和非开发人员使用；LangChain、LangGraph 是代码框架，灵活度高，便于做测试、版本管理、深度定制，适合复杂业务和需要集成进现有系统的场景。很多公司两者都用：先用 Dify 验证想法，再用代码实现生产版本。

### 模型输出的 JSON 格式不稳定怎么办

使用结构化输出功能（with_structured_output），优先使用厂商原生的 JSON Schema 模式，不支持时用工具调用方式；用 Pydantic 校验，校验失败时把错误信息反馈给模型重试；降低 temperature；在 schema 字段的 description 中写清楚要求。

## 项目经历怎么讲

用 STAR 结构：背景和要解决的问题、你的方案和技术选型理由、遇到的困难及解决方法、可量化的结果（如回答准确率从 60% 提升到 85%、平均响应时间、成本）。重点讲你做过的取舍和踩过的坑，而不是罗列用了哪些库。

## StudyMate 项目怎么讲

一句话介绍：基于 LangChain 和 LangGraph 的学习助手 Agent，支持混合检索 RAG 问答、工具调用、人工审批、多轮记忆，并用 FastAPI 部署为流式 Web 服务。

可以展开的技术点：

- **检索优化**：向量检索 + BM25 混合召回，RRF 融合，qwen3-rerank 精排；构建检索测试集，用命中率和 MRR 量化对比各方案（面试时报出你自己跑出来的真实数字）。
- **增量索引**：用内容哈希作为 chunk id，文档更新时只对变化部分调用 Embedding。
- **多 Agent**：Supervisor 模式（子 Agent 作为工具，上下文隔离）和 Map-Reduce 工作流（Send API 并行调研）两种实现，并能讲清楚各自的适用场景。
- **安全与稳定**：保存文件需要人工审批；计算器用 AST 白名单代替 eval；文件名清洗防止路径穿越；模型调用次数上限防止死循环。
- **工程化**：FastAPI 异步接口，SSE 流式推送 token、工具调用和审批事件；SQLite 持久化会话，服务重启不丢失；审批采用"中断 + 恢复"两段式接口。
- **测试**：用按剧本回复的假模型编写离线单元测试，覆盖工具执行、审批流程、会话隔离、接口协议，不依赖 API Key。

## 国内岗位常见技术栈

Python、LangChain/LangGraph、Dify/Coze 等低代码平台、FastAPI、向量数据库（Milvus、Elasticsearch）、国产大模型 API（通义千问、DeepSeek、智谱 GLM、文心）、Docker、基础的 Prompt Engineering 和模型评估方法。
