# Agent 工程化与部署

## 为什么用 FastAPI

FastAPI 是 Python 做 AI 服务的事实标准：原生支持 async，适合大量等待模型接口返回的 IO 密集型场景；用 Pydantic 自动校验请求参数；自动生成 /docs 交互式接口文档；原生支持 SSE 流式响应。

## 流式输出：SSE 还是 WebSocket

- **SSE（Server-Sent Events）**：基于普通 HTTP，服务端单向持续推送，格式是 `event: xxx` 和 `data: xxx` 加空行。实现简单，能穿过大多数代理和网关，ChatGPT 类产品和 OpenAI 接口的流式输出都用它。
- **WebSocket**：全双工双向通信，适合需要客户端频繁推送的场景，例如实时语音、协同编辑。

聊天类 Agent 首选 SSE。注意 Nginx 等反向代理默认会缓冲响应，需要关闭缓冲（proxy_buffering off），否则用户会看到内容一次性出现而不是逐字出现。

## 同步与异步

模型调用耗时几秒到几十秒，期间 CPU 基本空闲。异步（async/await）让一个进程在等待时去处理其他请求，大幅提高并发能力。在 FastAPI 的 async 接口中要使用 agent.ainvoke 和 agent.astream；如果在 async 函数里调用同步的阻塞方法，会卡住整个事件循环，导致所有请求都变慢。

## 会话持久化

开发时用的 InMemorySaver 把状态存在进程内存里，存在三个问题：重启后丢失；多个 worker 进程之间不共享；内存无限增长。生产环境换成 SqliteSaver（单机）或 PostgresSaver（多实例），只需要改 checkpointer，Agent 代码不用动。

短期记忆和长期记忆的区别：checkpointer 按 thread_id 保存单个会话的历史，属于短期记忆；跨会话的用户偏好、事实需要用 LangGraph 的 Store（按 namespace 存取键值，支持语义搜索），属于长期记忆。

## 人工审批的接口设计

Agent 触发 interrupt 后，接口不能一直挂起等待，而应该：把审批请求作为事件返回给前端并结束本次响应；前端展示审批界面；用户决定后调用单独的 resume 接口，带上 thread_id 和审批决定；服务端用 Command(resume=...) 从 checkpointer 恢复状态继续执行。这依赖持久化的 checkpointer，即使两次请求打到不同的服务实例也能正确恢复。

## 稳定性

- **超时与重试**：模型接口偶尔超时或限流（429），要设置超时时间，并对可重试的错误做指数退避重试（如 ModelRetryMiddleware）。
- **模型降级**：主模型不可用时自动切换到备用模型（ModelFallbackMiddleware）。
- **调用上限**：限制单次请求的模型调用次数和工具调用次数，防止死循环。
- **限流**：按用户或 IP 限制请求频率，保护服务和预算。
- **错误事件**：流式接口中途出错时，要发送一个 error 事件告诉前端，而不是让连接无声断开。

## 成本优化

- 简单任务用小模型，复杂任务再用大模型（模型路由）；
- 固定的系统提示词放在消息开头，利用厂商的上下文缓存折扣；
- 控制 RAG 注入的片段数量和长度；
- 长对话做摘要，清理过期的工具结果；
- 对相同的问题做缓存；
- 监控每个用户、每个功能的 token 用量。

## 安全

- **提示词注入**：用户输入或检索到的文档中可能包含"忽略之前的指令"之类的恶意内容。缓解方法：用分隔符区分指令和数据；对有副作用的操作加人工审批；工具遵循最小权限；不要把密钥放进提示词。
- **工具参数校验**：模型生成的参数不可信，必须校验。例如文件名要防止路径穿越（../），数学表达式不能直接 eval，SQL 必须参数化。
- **敏感信息**：日志和 tracing 中注意脱敏（如 PIIMiddleware），用户数据按权限隔离。

## 可观测性

每次请求记录完整的调用链：输入、每一步的模型调用和工具调用、耗时、token 用量、最终输出。LangSmith 只需配置环境变量即可自动追踪；也可以用 Langfuse 等开源方案私有化部署。线上问题排查、效果评估、成本分析都依赖这些数据。

## 部署

- 用 uvicorn 运行，多核机器可以开多个 worker（多 worker 时必须使用数据库版 checkpointer）；
- 用 Docker 打包，环境变量注入 API Key，不要把密钥写进代码和镜像；
- 健康检查接口（/health）供负载均衡和容器编排探活；
- LangGraph 官方也提供了 LangGraph Platform 托管部署方案。
