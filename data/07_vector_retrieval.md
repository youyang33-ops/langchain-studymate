# 向量检索与进阶 RAG

## Embedding 是什么

Embedding 模型把一段文本映射成一个固定长度的向量（例如 1024 维），语义相近的文本在向量空间中距离也近。"如何退货"和"怎么申请退款"字面不同，但向量很接近，这就是语义检索能处理同义表达的原因。

常用的中文 Embedding 模型：通义 text-embedding 系列、BGE（智源）、M3E、GTE。选型时看中文效果、向量维度（维度越高，存储和计算成本越高）、最大输入长度。注意：建索引和查询必须使用同一个 Embedding 模型。

## 相似度怎么算

- **余弦相似度**：比较两个向量的夹角，与向量长度无关，文本检索最常用。
- **点积（内积）**：向量已经归一化时，结果与余弦相似度等价，计算更快。
- **欧氏距离（L2）**：比较两点的直线距离，越小越相似。

## 向量索引：为什么不能暴力搜索

数据量小时可以逐个计算相似度（暴力搜索，Flat）。到了百万、千万级别就太慢了，需要近似最近邻（ANN）索引，用少量精度换大幅提速：

- **HNSW**：分层可导航小世界图。上层是稀疏的"高速公路"，下层越来越密，搜索时从顶层快速定位再逐层细化。查询快、召回率高，但占内存多，是目前最常用的索引，Chroma、Milvus、pgvector 都支持。
- **IVF**：先用聚类把向量分成很多桶，查询时只搜索最近的几个桶。
- **PQ（乘积量化）**：把向量压缩成短编码，大幅节省内存，常与 IVF 组合成 IVF-PQ。

## 向量数据库选型

- **Chroma**：轻量，pip 安装即可使用，适合学习和原型。
- **Milvus**：国内用得最多的开源向量数据库，支持分布式和海量数据。
- **pgvector**：PostgreSQL 插件，已经在用 PG 的团队无需引入新组件。
- **Elasticsearch**：同时支持全文检索和向量检索，做混合检索很方便。

## BM25 关键词检索

BM25 是经典的关键词检索打分算法，搜索引擎和 Elasticsearch 默认都用它。核心思想：一个词在文档中出现越多越相关，但增益会饱和（由参数 k1 控制，常取 1.2 到 2.0）；这个词在所有文档中越少见，区分度越高（IDF）；长文档要做长度归一化（由参数 b 控制，常取 0.75）。

向量检索擅长语义和同义表达，但对专有名词、产品型号、错误码、人名这类精确匹配反而不如 BM25。

## 混合检索与 RRF

混合检索同时进行向量检索和 BM25 检索，再把两路结果融合。两种分数量纲不同，不能直接相加，常用 RRF（Reciprocal Rank Fusion，倒数排名融合）：每条结果的得分是它在各路结果中排名倒数之和，score = Σ 1/(k + rank)，k 一般取 60。RRF 只看排名，不需要调权重，简单稳健。

## 重排序 Rerank

检索分两阶段：

1. **召回（粗排）**：用 Embedding 向量检索和 BM25，从海量数据中快速找出几十条候选。Embedding 是双塔模型（Bi-Encoder），问题和文档分别编码，文档向量可以提前算好，所以快。
2. **精排**：用 Rerank 模型对候选重新打分，取前几条。Rerank 是交叉编码器（Cross-Encoder），把问题和文档拼在一起输入模型，能捕捉两者之间细粒度的交互，精度明显更高，但每一对都要实时计算，只能用于少量候选。

常用 Rerank 模型：bge-reranker 系列、通义 qwen3-rerank。

## 查询改写

- **指代消解**：多轮对话中用户问"那它和 LangChain 有什么区别"，要结合历史改写成"LangGraph 和 LangChain 有什么区别"再检索。
- **多查询（Multi-Query）**：让模型把问题改写成多个不同表述，分别检索后合并，提高召回率。
- **HyDE**：先让模型生成一个假设性的答案，用这个答案去检索。答案和文档的表述更接近，有时比用问题检索效果更好。
- **问题拆解**：复杂问题拆成多个子问题分别检索。

## 切分策略进阶

- **按结构切分**：Markdown 按标题、代码按函数、PDF 按章节，保持语义完整。
- **父子文档**：用小块做检索保证精准，命中后返回它所属的大块，保证上下文完整。
- **语义切分**：根据相邻句子 Embedding 的相似度变化找切分点。
- **给 chunk 加上下文**：在每个 chunk 前补充文档标题和章节路径，避免切分后丢失"这段在讲什么"。

## 增量索引

文档会持续更新，每次全量重建索引既慢又浪费 Embedding 费用。常见做法是用"来源 + 内容"的哈希值作为 chunk 的 id：新 id 写入，消失的 id 删除，不变的 id 跳过。

## RAG 评估指标

检索阶段：

- **命中率（Hit Rate / Recall@k）**：正确片段出现在前 k 条结果中的比例。
- **MRR（平均倒数排名）**：正确片段排第 1 得 1 分、排第 2 得 1/2 分，依此类推，再取平均，衡量正确结果排得是否靠前。

生成阶段：

- **忠实度（Faithfulness）**：回答中的每个论断是否都有检索资料支撑。
- **答案相关性**：回答是否切题。

工具：Ragas、LangSmith 评估。最重要的是自己构建一个覆盖真实问题的测试集，每次修改切分、检索、提示词后跑一遍，用数据说话。
